Lesson 1 of 8

A recipe Claude keeps

You can identify one task at work that’s worth turning into a skill and another that isn’t.

Every week, you paste the same instructions into Claude: the tone, the format, what must never be left out. Forget one line, and the answer no longer follows the standard. This lesson explains what a skill is and which tasks it’s worth using one for.

In 1 minute

  1. A skill is a recipe you write once and Claude keeps.
  2. It opens the recipe on its own when the request matches it.
  3. It’s useful for tasks you repeat the same way. You don’t need one for a one-time task.

1You repeat the same instructions every time

In a new conversation, Claude doesn’t remember how you work. So you paste everything in again: the tone, the length, the prices. When the list is long, something always gets left out.

A skill solves this. You write the instructions once. Claude starts following them whenever you make that kind of request.

Débora responds to about fifteen bath and grooming price requests a day. Before, she pasted eight lines with the price list and the shop’s tone into Claude. With the skill, she only pastes the customer’s message.

2The skill opens on its own when the request matches

You don’t need to call the skill by name. Claude looks at the list of your skills and reads a short sentence for each one: its description. If the request matches, Claude opens that skill and follows what’s written.

The others stay closed and don’t get in the way. That’s why you can have several skills, one for each task.

Raul has two skills: one for employment law opinions and another for client update emails. When he asks, "summarize today’s hearing for the client," Claude opens only the email skill.

3It works for things that repeat the same way

Writing a skill takes about twenty minutes. It’s worth it when a task comes up every week and you want the same result every time.

Three cases don’t call for a skill. A one-time task can be handled in the conversation. Information that changes every day, like today’s schedule, doesn’t fit a fixed recipe. And a rule that applies to every conversation belongs in personal preferences, which are in the app’s Settings.

Débora sorted her tasks into two cards before creating her first skill.

Test yourself

Raul wants Claude to always write in formal Portuguese, in every conversation. What should he do?

Stuck here? That's normalThe line between a skill and a regular conversation can be confusing at first. Ask yourself one question: “Will I ask for this again, the same way, next week?” If the answer is yes, the task is a good candidate.

The description decides when the skill is used

You can write the description for your future skill in 200 characters or less, saying what it does and when to use it.

A skill with a vague description sits unused in the list: Claude doesn’t realize it’s useful. A description that’s too broad does the opposite and appears when it shouldn’t. The right sentence solves both problems.

In 1 minute

  1. Claude decides whether to open the skill by reading only its description.
  2. A good description says what it does and when to use it, using the words you use when making a request.
  3. In the Claude app, it can be up to 200 characters.

1Claude chooses by the label

A skill has two parts that matter here: its name and its description. When you make a request, Claude hasn’t read any skill in full yet. It only has these two lines for each one.

The name is lowercase, with a hyphen in place of a space. Don’t worry about that: in lesson 5, Claude will write the name for you.

That’s why the description is the most important part. Great instructions are no use if the skill is never opened.

Raul’s first skill had the description "Helps with legal documents." He requested an employment law opinion, and Claude didn’t open the skill: the sentence didn’t mention employment law opinions.

2Say what it does and when to use it

A good description has two parts. The first says what the skill does, starting with a verb: "Builds," "Answers," "Writes." The second says when to use it, with the situations where it should be used.

Write as if you’re introducing the skill to someone else. Avoid "I am" or "you should": the description talks about the skill, not to Claude.

Raul rewrote the vague sentence. Take a look at both cards.

Want to know why there’s a limit?

Claude reads the description of all your skills with every request. Short sentences make that reading quick and keep one skill from “spilling over” into another’s topic. Other programs that use skills have a higher limit, but a short sentence works in all of them.

3Use the words you use when you make a request

Claude compares your request with the description. If you write “notice that a pet is ready” and the description says “notification of service completion,” the connection is weak. Put the words you actually say in the description.

Débora tested two descriptions for the same skill. She made the same request both times.

Test yourself

Débora often asks, “Write the post for Saturday’s promotion.” Which description is most likely to open?

Stuck here? That's normal200 characters may not seem like much. Write your first draft without a limit. Then cut adjectives and repeated examples. Keep “use when”; you can remove the rest.

Turn on the skills that come ready

You can turn on skills in the Claude app and watch one of them create a Word document for you.

Many people have never seen a skill in action and don’t even know whether it’s turned on in the app. In just a few minutes, you can turn it on, check, and see Claude use a ready-made recipe. Then your skill will go in the same place.

In 1 minute

  1. Skills depend on one setting: Code execution and file creation.
  2. The list of skills is under Customize › Skills.
  3. The ready-made ones handle Word, Excel, PowerPoint, and PDF without you having to ask.

1First, turn on file creation

A skill only works if Claude can open and create files in the conversation. This permission has a long name: Code execution and file creation. It only lets Claude create files inside the conversation: nothing leaves your computer.

On individual plans, including the free plan, you turn it on yourself. In a company account, the account manager enables it for everyone.

Débora opened Claude on the store computer and found the switch turned off. It took just one click.

2The list is under Customize › Skills

With the switch on, the app shows the list of skills. There you'll see Anthropic's ready-made skills—the company that makes Claude—followed by your own. Each one has its own on/off switch. Note: these are two different places. The general switch is under Settings; the list is under Customize.

The ready-made skills handle office files: Word, Excel, PowerPoint, and PDF. You don't need to call any of them by name.

Raul checked the list before creating anything. All four were on, and he saw where his skill would appear.

To be sure, open Claude's reasoning. It's just above the answer, collapsed into a line. Tap it and look for the skill's name. The ready-made skills appear under the file type name in English: the Word one is "docx".

Lesson 4 of 8

Inside, a skill is organized text

You can read a skill and say what the header, instructions, and example do.

The word skill sounds like something for programmers. Inside, it’s organized text, like the procedure you’d write for an intern. Seeing a real one takes away the fear and shows you what you’ll need to write.

In 1 minute

  1. A skill is a folder with a main file, SKILL.md.
  2. It has a header with a name and description, followed by the instructions.
  3. An example of a good response teaches more than ten commands.

1A folder with a text file

Every skill is a folder. Inside it is a plain text file called SKILL.md. The ".md" at the end is just the file type, like Word’s ".docx". Only this file is required.

The folder name is the skill name, in lowercase, with a hyphen in place of each space. If the task needs a model or a large table, those files go in the same folder.

Raul’s employment law opinion skill is a folder with two files: SKILL.md and the opinion template the office has used for years.

2Header on top, instructions below

SKILL.md starts with a header, between two lines of three dashes. It contains the name and description you practiced in lesson 2. Didn’t take lesson 2? The description is the sentence that says what the skill does and when to use it.

Below the header are the instructions, written for someone new to the team. At the end, there’s an example of a good response.

This is Débora’s bath and grooming estimate skill, in full. Read from top to bottom.

Test yourself

A customer asks the price of grooming. Which part of Débora’s skill makes Claude open it?

3Explain why instead of shouting orders

Claude takes what’s written in the skill literally. All-caps orders with “never” and “always” make it overdo the rule. A sentence explaining why works better: it understands when the rule applies.

Raul had written the rule about legal summaries the old way. See what changed when he explained why.

Want to know how much the skill can grow?

Keep SKILL.md short, well under 500 lines. Put anything long, like a hundred-row table, in a separate file in the same folder. In SKILL.md, add one line: "the full table is in tabela-precos.docx".

Stuck here? That's normalThe three dashes and "name:" look like code. They’re just labels, like the subject of an email. In lesson 5, Claude writes this for you; for now, you only need to know how to read it.

Create yours by talking with Claude

You can finish a conversation with a ZIP file of your first skill, ready to upload.

Writing SKILL.md by hand requires a text editor, the right file name, and care with the dashes in the header. You don’t need to do that. Claude interviews you, writes the skill, and gives you the zipped folder.

In 1 minute

  1. Ask Claude to use the skill-creator skill and tell it about your task.
  2. Answer its questions with real examples, not with “the usual.”
  3. Review the text and ask for the folder as a ZIP file.

1Start with the right request

Anthropic provides a ready-made skill that teaches Claude to create skills: skill-creator. Ask Claude to use it, describe the task, and share what you already have.

Before writing, it asks questions. It’s a short interview about how you do the task.

Raul opened a new conversation and pasted the request below. He got three questions before Claude wrote anything.

2Answer with real examples

The quality of the skill depends on your answers. “The usual” becomes a vague instruction, and Claude fills in the rest with the most common approach. A real example gives it a rule it can follow.

Débora created the budgeting skill. Claude asked, “What if the client doesn’t say how big the pet is?” See the two possible answers.

Stuck here? That's normalThe list of questions can sometimes be long. Answer what you know and write: “For the rest, choose the simplest option and tell me what you chose.” You can review it afterward.

3Review the text and ask for the ZIP

When it’s done, Claude shows the skill files next to the conversation. Read SKILL.md and check three things. The name at the top matches the folder name. Your description is in the header. And there’s an example at the end.

Lesson 7 of 8

Test the skill with and without it

You can test your skill with 4 requests and note where it gets things right and where it fails.

A successful test shows that the skill opens. It doesn’t show whether it opens every time or whether the result is better than without it. Four carefully chosen requests answer both questions.

In 1 minute

  1. Test two requests that should open the skill, worded in different ways.
  2. Test one that shouldn’t: a similar request, but about a different subject.
  3. Repeat one request with the skill turned off and compare.

1Ask the way you really would

When you’re in a hurry, no one writes a request the same way twice. Your skill needs to open both ways. Try a full sentence and a shortened version, like you’d type on your phone.

How can you tell if it opened? Tap reasoning, just above the answer, and look for the skill’s name. Or check whether the answer uses something only the skill has, such as a price from the price list. If the block doesn’t appear, ask: "Did you use any skills in this answer? Which one?"

If one version fails, the problem is almost always in the description: it’s missing the words you used in that version of the request.

Débora tested two real messages from customers. The second was written the way many people write on WhatsApp.

2A similar request that isn't hers

The reverse test matters too. Make a request from the same area, but for a different task. The skill should stay closed.

If it opens when it shouldn't, the description is too broad and will get in the way of requests that aren't meant for it.

Raul asked for a short email to the client. The employment law opinion skill shouldn't have come in. See what happened, and how it looked after the fix taught in lesson 8.

3Compare with the skill turned off

You still need to know whether the skill improves the result. Turn off its switch in Customize › Skills, open a new conversation, and repeat one of the requests. Then turn it back on.

Débora repeated the request about the medium poodle with the skill turned off.

Lesson 8 of 8

Fix it, maintain it, and know when to stop

You can fix a skill failure, upload the new version, and decide what shouldn't become a skill.

Every skill fails on some request. Giving up at that point wastes the work you've done. The fix is often just one sentence, and knowing where to make the change saves you from starting over.

In 1 minute

  1. Didn't open, or opened when it shouldn't have? Fix the description.
  2. Opened and gave the wrong answer? Fix the instructions or the example.
  3. A rule for every conversation, a single client's situation, or data that changes shouldn't become a skill.

1Every failure has its place for a fix

The notes from lesson 7 show you where to make changes. If the skill didn't open, or opened when it shouldn't have, the problem is in the description. If it opened and the answer was wrong, the problem is in the instructions or the example.

Change one thing at a time and test again. That way, you know what fixed it.

In lesson 7, the request "how much to give my little pet a trim?" didn't open Débora's skill. She changed only the description.

2Request the correction and replace the version

You don’t need to rewrite the skill. Go back to the conversation where it was created, in lesson 5: it’s in the recent conversations list in the side menu. Can’t find it? Open a new conversation and attach the skill ZIP from Documents using the paperclip button. Describe the problem and ask for only the necessary change, with the new ZIP at the end.

To replace the version, first save the new ZIP in Documents; the old one will still be there. Then open the skill in Settings › Skills, click the three dots (…), choose Delete, and upload the new ZIP using the steps from lesson 6.

Raul’s test showed that the employment law opinion skill opened for a simple email. He went back to the conversation from lesson 5.

Stuck here? That's normalDeleting the old version feels risky. The new ZIP is already on your computer, and the old one is there too, in the Documents folder. If the new version turns out worse, delete it and upload the old one again.

3What shouldn’t become a skill

After making your first one, you may want to turn everything into a skill. Three things fit better elsewhere in the app. A rule for every conversation belongs in personal preferences. A client’s matter, with documents and history, belongs in a project. Information that changes all the time comes through a connector.

And use one skill per task. Several small ones work better than one huge skill that tries to do everything.
